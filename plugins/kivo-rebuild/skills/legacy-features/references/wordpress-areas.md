# WordPress areas

The areas to split a legacy WordPress site into, what to look for in each, and the domain each belongs to for the parity audit. One `legacy-area-inventory` agent takes one area. Name an area in lowercase kebab case, as in the first column.

Read the code and the options, never run a write. A database is read with SELECT statements on a local clone only.

| Area | Domain | What to look for |
|---|---|---|
| `plugins` | integrations | Active plugins from `wp_options.active_plugins` and network-active plugins, and the files in `mu-plugins`. One feature per plugin behavior in use, not one per plugin. |
| `theme` | storefront | The child theme's `functions.php`, templates that override a shop plugin's templates, shortcodes registered by the theme, image sizes, menus and widget areas, and theme support flags. |
| `theme-options` | tracking | `theme_mods_*` and theme options pages: header and footer script fields, builder blocks placed by an option, announcement bars, social links, contact details printed in templates. |
| `post-types` | content | Custom post types and taxonomies whose content the templates show (banners, sliders, testimonials, store locations), and their scheduling fields (start and end dates, display order). Count the posts. |
| `acf-options` | content | ACF options pages and the fields on them, and field groups attached to templates. Count the fields in use. |
| `checkout` | checkout | Extra checkout fields, validations (document numbers, postcode lookups), captchas, guest checkout and registration settings, order notes, coupon rules, order statuses added by code. |
| `shipping` | checkout | Shipping zones and methods, free shipping thresholds, quote calculators, pickup points, delivery date pickers. |
| `payments` | checkout | Payment gateways and their modes, installment rules, discounts by method, webhooks that confirm payments. |
| `emails` | checkout | Transactional e-mail templates overridden in the theme, e-mails sent by plugins, SMTP or API senders, and the triggers of each. |
| `integrations` | integrations | Outbound HTTP calls (`wp_remote_*`, SDK clients), webhooks, REST consumers recognizable by user agent in the logs, ERP, CRM, marketplace and feed integrations. |
| `cron` | infrastructure | Scheduled hooks (`wp_next_scheduled`, Action Scheduler jobs), their intervals, and what each job does. |
| `tracking` | tracking | Scripts outside the tag manager: analytics, pixels, chat widgets, consent banners, data layer pushes in templates, server-side events. |
| `infrastructure` | infrastructure | Guards and tuning: XML-RPC settings, image regeneration, rate limits, security headers, `.htaccess` or server rules in the repository, caching rules, robots rules. |
| `redirects` | content | Redirect plugins and their rules, `.htaccess` redirects, redirects added in code. Count the rules; they feed the approved redirects of the inventory. |
| `search` | storefront | Search plugins or custom search, filters and facets, autocomplete, the pages and parameters they create. |
| `feeds` | integrations | RSS and product feeds, sitemaps generated by code, other machine-readable endpoints. |
| `forms` | integrations | Form plugins, their notification e-mails, spam protection and the destinations they send submissions to. |

Domains used by the audit: storefront, checkout, content, integrations, tracking, infrastructure. Every area belongs to exactly one domain; add a row and a domain when the site has an area that fits none of these.

## What a good item looks like

- One feature per behavior a visitor, editor or integration can observe, not one per file.
- Features configured but not coded are features: a script pasted in an option, a banner placed by a setting.
- The `data` object counts what the feature depends on (posts of a type, orders with a meta key, redirect rules), as integers.
- `source` is something a person can open: `file:line`, an option name or a plugin slug.
