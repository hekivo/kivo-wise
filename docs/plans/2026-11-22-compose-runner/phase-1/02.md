# Component 02 — Compose session context and hook guards

Phase 1, batch B. Depends on: 01 (runner `compose`, `runtime.compose`, `runtime.session`, `sessionKind`).
Spec: S-3 (session context, `protect-files`), S-2 (detection cache), S-6 (corpus line), S-7 (hook goldens).
Decisions: D-006, D-009, D-010, D-013, D-016. One pull request,
`feat(hooks): compose runner context, session-aware cache and override guard`.

## Goal

The hooks print a correct runner line and commands rule for Compose projects, keep the detection cache
honest across host and container sessions, report an unavailable corpus outside local sessions, protect
the personal Compose override, and kivo-creator reads the runner the detector chose.

## Files

- `hooks/lib.mjs` — `runnerLine()`, `commandsLine()`, `rulesLine()`, `readCache()`/`writeCache()`,
  `currentSessionKind`.
- `hooks/protect-files.mjs` — Compose override rule and `isGitignored`.
- `hooks/post-edit-reminder.mjs` — no logic change expected (`cacheCommand()` is runner-neutral); golden
  only.
- `plugins/kivo-creator/scripts/lib/stack.mjs` — runner precedence.
- `test/hooks/fixtures/detector-sage-compose.mjs` — fake detector printing a `compose-bin` detection.
- Goldens under `test/hooks/` (below), `test/hooks.test.mjs`, `test/creator/stack.test.mjs`.
- `plugins/kivo-wise/` — regenerated.

## Steps

### 1. Runner line and commands rule (AC-02-1, AC-02-2)

1. Test first: `test/hooks/fixtures/detector-sage-compose.mjs` prints the detection of the
   `compose-bin` fixture (copy the JSON the component 01 detector produces, with `runtime.session.kind`
   `local`). Golden `test/hooks/session-start/sage-compose` expects:
   - `runner: compose · wp=bin/wp · acorn=bin/wp acorn · composer=bin/composer · node=bin/npm · test=bin/test · lint=bin/mago · cache=bin/flush · logs=bin/logs`
   - the commands rule with the example `` `bin/wp acorn optimize:clear` `` and the clause
     "from the project root" (D-013).
2. `runnerLine()` needs no change for the compose line itself (it is built from `RUNNER_KEYS`); change
   the `none` text to
   `runner: none detected (no Lando, Compose or DDEV environment); use the commands the project documents`.
3. `commandsLine()`: when the runner is `compose`, insert ", from the project root," after the example.
   Lando and DDEV keep today's string exactly.
4. A test asserts `buildContext()` for `sage-compose` is at most `MAX_CONTEXT_CHARS` and pins its exact
   length, so a later wording change is a visible diff.
5. Update `test/hooks/session-start/sage-bedrock-no-runner` (wording only); every other session-start
   golden stays byte-identical.

### 2. Session-aware detection cache (AC-02-3)

1. `currentSessionKind(env = process.env)` in `hooks/lib.mjs` with the same order as the detector's
   `sessionKind` (the Codex mirror ships `hooks/` without `scripts/`, so the hook cannot import the
   detector). A parity test imports both and checks every signal and the `local` default.
2. `writeCache()` stores `sessionKind` next to `savedAt` and `root`; `readCache()` returns `null` when the
   stored kind is missing or differs from `currentSessionKind()`.
3. Test: write a cache with kind `local`, run with `CODESPACES=true` (the golden runner's `env.json`),
   and assert the detector runs again; a matching kind still reads from the cache.

### 3. Corpus line outside local sessions (AC-02-4)

1. `rulesLine()`: keep only configured corpus roots that exist on disk. When none remain and
   `detection.runtime.session.kind` is not `local`, print
   `corpus: unavailable in this environment; web last: official documentation hosts` in place of the
   `corpus second (…), web last` clause. Local sessions keep `none configured` and today's text.
2. Golden `test/hooks/session-start/cloud-no-corpus`: detection with `session.kind` `cloud` and a
   corpus root that does not exist.
3. Test that a detection without `runtime.session` (an older cached detection or an older detector)
   is treated as `local`.

### 4. Compose override guard (AC-02-5)

1. `isGitignored(root, rel)`: read the project `.gitignore`, skip blank lines, comments and `!`
   negations, trim a leading `/`, and match the literal path. No glob engine.
2. In `protect-files.mjs`, for `compose.override.yaml`, `compose.override.yml` and
   `docker-compose.override.yml` at the project root, deny when `isGitignored` is true with the hook's usual prefix followed by
   `<rel> is the developer's unversioned Compose override; change compose.yaml instead.`
3. `bin/` scripts are never denied (D-012: wp-kit owns them).
4. Goldens: `test/hooks/protect-files/compose-override-deny` (gitignored override) and
   `test/hooks/protect-files/compose-override-tracked-allow` (same file, not in `.gitignore`), plus a
   unit test that an edit to `bin/wp` is allowed.

### 5. Cache reminder (AC-02-6)

Golden `test/hooks/post-edit-reminder/compose-cache-command`: a PHP edit under the active app of the
compose detection prints `` run `bin/flush` before testing ``. If the golden already passes with no code
change, keep it as the regression proof.

### 6. kivo-creator runner precedence (AC-02-7)

1. `plugins/kivo-creator/scripts/lib/stack.mjs:39`: `runner: detection?.runtime?.runner ?? flag?.runner ?? 'none'`.
   The detector now applies the flag override with its guards (component 01, D-010), so reading the flag
   first would disagree when the flag names a missing environment.
2. `test/creator/stack.test.mjs`: a compose detection gives `compose`; a detection whose flag says
   `compose` while the detector kept `lando` gives `lando`.
3. kivo-creator is a hand-authored plugin: no version bump by hand (release-please owns it).

### 7. Checks (AC-02-8)

`node --test test/*.test.mjs test/creator/*.test.mjs test/rebuild/*.test.mjs`,
`node scripts/sync-cursor-hooks.mjs --check`, `node scripts/build-codex-plugin.mjs` then `--check`,
`node scripts/validate-skills.mjs`. Hook outputs never contain environment values other than the session
kind (D-006).
